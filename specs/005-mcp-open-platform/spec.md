# Spec 005: MCP 开放平台（只读 MCP Server + `/open` 站点）

**Status:** Draft
**Created:** 2026-08-13
**Branch:** `005-mcp-open-platform`
**Alignment:** `inputs/alignment.md`（唯一需求来源，方向已封板）

---

## 1. Problem Statement

SFA CRM 已在公网可用（https://crm.pmyangkun.com），但**只能被人用浏览器打开使用**。与此同时，主流 AI 助手（WorkBuddy / Claude Code / Claude Desktop / Cursor / Codex）已普遍支持通过 MCP 接入外部业务系统——**却没有任何途径把 SFA CRM 接进去**。

现状缺口：

- 系统内已有 15 个 agent 工具，但只能被内置的 Copilot 侧栏调用，**外部 AI 助手完全触达不到**
- 唯一的身份凭证来自浏览器登录换取的短期令牌，**程序无法提前持有、无法写入配置文件**
- 没有对外的接入入口、没有工具契约说明、没有任何"这个系统可以被 AI 连接"的门面

要解决的问题：**让任何支持 MCP 的 AI 助手，在一分钟内、零注册地连上线上 CRM 并读到真实业务数据**；同时对外呈现一个可信、可自证的开放平台门面。

---

## 2. Goals (Top 3)

1. **一分钟零注册接入**——访客打开站点，点一下选身份，复制配置，粘进自己的 AI 助手，即可提问并得到真实业务数据。全程不注册、不填手机号、不输密码。
2. **身份即数据范围**——同一个接入地址、同一套工具，换一把密钥看到的数据范围完全不同（销售只见己、主管可见全队）。把系统内已有的数据可见性能力第一次对外呈现。
3. **不绕弯路**——首屏之后直接进入接入流程，不在访客动手之前插入任何需要先看完的铺垫内容。

---

## 3. Non-Goals（明确不做）

- ❌ **任何写操作**——不暴露创建线索、录跟进、转化、释放、标丢失等能力。写入必须走既有的表单人工确认路径，本期不为 AI 开任何写入口
- ❌ **OAuth 2.1 / 动态客户端注册**——只读演示场景下属纯负担
- ❌ **MCP Resources 与 Prompts**——本期只实现 Tools 一类能力
- ❌ **Skill**（教 AI 如何使用本平台的指导包）——理由见 `inputs/alignment.md` §9.2：只读且扁平的工具集没有跨工具流程需要编排，撑不起说明书。触发条件为"启动写操作那一版"，届时与写操作同期交付
- ❌ **CLI**——下期做，方向见 `inputs/alignment.md` §9.3
- ❌ **多租户 / 接入真实客户数据**——演示环境只承载虚构数据
- ❌ **为任何单一客户端定制**——产出物是标准 MCP 服务，WorkBuddy 只是首个验证对象

---

## 4. User Stories

### US1 [P0]：访客零门槛接入并问出第一个答案

**As a** 一个刚从文章/朋友转发点进来的访客（没有账号、不打算注册）
**I want to** 在开放平台页面上选一个身份、复制一段配置、粘进我自己的 AI 助手
**So that I can** 立刻用自然语言向一个真实运行的 CRM 提问并得到真实数据

**Why P0：** 这是整个 spec 的存在理由。没有它，其余一切都没有落点。

**Independent Test：** 用一台干净机器打开 `/open` → 点"以主管身份连接" → 复制配置 → 粘进任一支持 MCP 的客户端 → 提问"我团队哪几单有风险" → 收到非空的真实业务数据。全程无需注册或登录。

**Acceptance Criteria:**

1. **Given** 访客首次打开 `/open`，**When** 页面加载完成，**Then** 无需任何输入即可看到接入地址与两个身份入口
2. **Given** 访客点击某个身份按钮，**When** 密钥生成成功，**Then** 页面原地展开该身份的完整配置内容（不跳转页面），并提供一键复制
3. **Given** 访客未填写任何个人信息，**When** 完成上述操作，**Then** 全流程必填字段数为 0
4. **Given** 访客已把配置粘入其 AI 助手，**When** 其助手发起连接，**Then** 连接成功且能列出全部 9 个可用工具
5. **Given** 连接已建立，**When** 访客提出业务问题，**Then** 助手能调用工具并返回真实（虚构演示数据但非空、非编造）的业务结果

---

### US2 [P0]：身份决定可见范围

**As a** 想理解"AI 接入企业系统时权限边界如何传递"的观察者
**I want to** 用两种不同身份的密钥问同一个问题
**So that I can** 直观看到同一接入地址、同一套工具返回的数据范围截然不同

**Why P0：** 这是本平台区别于"一个公开查询接口"的核心价值，也是唯一能对外展示既有数据可见性能力的场合。

**Independent Test：** 用销售身份密钥与主管身份密钥分别提问"哪几单有风险"，比对返回条目集合——销售返回的应是主管返回结果的真子集。

**Acceptance Criteria:**

1. **Given** 使用销售身份密钥，**When** 查询线索/客户/风险单/团队汇总，**Then** 只返回该销售名下的数据
2. **Given** 使用主管身份密钥，**When** 提出同一问题，**Then** 返回整个团队范围的数据
3. **Given** 任一身份，**When** 试图通过工具参数绕过范围（如指定他人名下的线索标识），**Then** 系统拒绝或返回空，不泄露范围外数据
4. **Given** 两种身份，**When** 分别列出可用工具，**Then** 工具清单一致（差异只体现在数据范围，不体现在能力清单）

### US4 [P1]：公开暴露下的稳定与安全

**As a** 这个演示环境的维护者
**I want to** 在完全公开、鼓励分享的前提下，平台不被拖垮、不成为攻击他人的跳板
**So that I can** 长期开着它而不用盯着

**Why P1：** 公开发放密钥意味着放弃了访问控制这道防线，其余防线必须成立，否则平台开不长。

**Independent Test：** 用单一密钥持续高频调用触发限流；在演示数据中植入伪装成指令的文本，验证其被标记为不可信内容后再返回。

**Acceptance Criteria:**

1. **Given** 单个密钥的调用频率超过额度，**When** 继续调用，**Then** 请求被拒绝并返回人类可读的说明
2. **Given** 同一来源反复领取密钥，**When** 超过每日领取上限，**Then** 拒绝发放
3. **Given** 演示数据中的用户可编辑文本包含疑似指令内容，**When** 该内容通过工具返回，**Then** 被明确标记为不可信数据并做长度截断
4. **Given** 演示数据每 30 分钟重置，**When** 重置发生，**Then** 已发放的密钥仍然有效，访客连接不中断
5. **Given** 密钥已过期，**When** 访客的助手继续调用，**Then** 返回的错误信息中包含人类可读的续期指引（该信息会被助手直接转述给用户）
6. **Given** 任何身份的任何调用，**When** 试图执行写入，**Then** 平台不提供任何写入能力（工具清单中不存在写操作）

---

### US5 [P2]：自助查阅工具契约与接入文档

**As a** 想在自己项目里参考、或想先看清楚有哪些能力的技术读者
**I want to** 不接入也能查到每个工具的完整参数、返回结构与接入步骤
**So that I can** 评估这套东西的设计，或照着接入到我用的客户端

**Why P2：** 提升可信度与传播性，但不阻塞核心链路。

**Independent Test：** 直接访问工具页与文档页，核对 9 个工具的参数与返回描述完整、各客户端接入步骤可照做。

**Acceptance Criteria:**

1. **Given** 访客访问工具页，**When** 页面加载，**Then** 展示全部 9 个工具的名称、用途、入参（含必填标识）、返回结构与示例问法
2. **Given** 访客访问文档页，**When** 查看接入章节，**Then** 至少覆盖 WorkBuddy / Claude Code / Claude Desktop / Cursor / Codex 五种客户端，每种给出可直接照做的步骤
3. **Given** 某客户端的凭证写法与其他不同（如需先设置环境变量），**When** 查看该客户端章节，**Then** 其差异步骤被单独说明，而非套用统一模板
4. **Given** 一个 AI 助手访问纯文本接入说明，**When** 读取完毕，**Then** 其中包含生成自身配置所需的全部信息（接入地址、凭证位置、工具清单）

---

### Edge Cases

- 访客用已过期的密钥连接 → 返回带续期指引的可读错误，而非无声失败
- 访客同时领取两个身份的密钥并配置成两个连接 → 两者互不干扰，各自维持自己的数据范围与额度
- 访客在演示数据重置的瞬间发起调用 → 不返回半截数据，不使连接失效
- 访客的助手请求了不存在的线索标识 → 返回明确的"未找到或不在可见范围内"，不区分二者以免探测
- 访客的助手一次性连续调用多个聚合类工具 → 受限流保护，不拖垮服务
- 移动端访客完成接入流程 → 与 PC 端信息与操作完全等价，不出现"请到电脑上操作"
- 演示区凭证若被滥用 → 其额度独立，耗尽不影响正常访客

## 5. Functional Requirements

### 5.1 密钥发放与身份

- **FR-001**：系统 MUST 提供两种演示身份——销售（`sales01` 王小明）与主管（`manager01` 陈队长），且不提供管理员身份
- **FR-002**：访客 MUST 能在不注册、不登录、不提供任何个人信息的前提下领取密钥
- **FR-003**：系统 MUST 在密钥生成后原地展示完整配置内容并支持一键复制，不得跳转页面
- **FR-004**：密钥 MUST 有 7 天有效期，过期后不可用
- **FR-005**：系统 MUST 只保存密钥的不可逆摘要，明文仅在生成时返回一次
- **FR-006**：系统 MUST 支持吊销单个密钥
- **FR-007**：系统 MUST 限制同一来源的密钥领取频率（默认每日 30 次）。取值须顾及共用出口 IP 的场景——一间办公室或一个会场往往共用一个 IP，而每位访客通常要领两把（销售 + 主管）
- **FR-008**：访客 MUST 能查询自己密钥的状态（所属身份、剩余有效期、已调用次数）

### 5.2 MCP 接入与工具

- **FR-009**：系统 MUST 提供符合 MCP 规范的接入端点，支持连接握手、工具列举、工具调用三类交互
- **FR-010**：系统 MUST 仅暴露标记为只读的 9 个工具：线索搜索、线索详情、跟进历史、MEDDICC 评估、客户列表、风险单扫描、团队 MEDDICC 汇总、重点关注单、预测分类分布
- **FR-011**：系统 MUST 通过工具自身的只读标记进行过滤，而非人工维护清单，以保证未来新增工具不会被误暴露
- **FR-012**：系统 MUST NOT 暴露任何导致数据变更的工具，包括既有的 6 个引导型（导航预填）工具——它们依赖浏览器跳转，对无浏览器的调用方无意义
- **FR-013**：每次工具调用 MUST 依据密钥所属身份施加既有的数据可见性规则，不得新建独立的权限逻辑
- **FR-014**：无论身份如何，工具清单 MUST 保持一致，身份差异只体现在返回的数据范围

### 5.3 开放平台站点

- **FR-015**：站点 MUST 位于 `/open` 路径下，并为工具契约、接入文档、纯文本接入说明各提供独立页面
- **FR-016**：首页 MUST 依次包含：接入地址与价值主张、**三步接入（身份选择 → 配置展示 → 重启提问）**、示例问句、工具总览与声明页脚。接入流程 MUST 紧跟首屏，前面不插入任何需要先阅读或先观看的铺垫段落
- **FR-017**：站点 MUST 为 WorkBuddy / Claude Code / Claude Desktop / Cursor / Codex 五种客户端各提供可直接照做的配置内容
- **FR-018**：对凭证写法不同的客户端，站点 MUST 单独给出其差异步骤
- **FR-019**：站点 MUST 提供可被 AI 助手直接读取的纯文本接入说明，内容足以让助手自行生成配置
- ~~**FR-020**：首页 MUST 提供可运行的演示区~~ —— **2026-08-16 撤销**，见 US3
- ~~**FR-021**：演示区所用凭证 MUST NOT 下发至前端可见内容~~ —— 随 FR-020 撤销。**若日后恢复演示区，本条必须一并恢复**
- **FR-022**：站点在移动端 MUST 与 PC 端完全等价，不得出现任何"移动端暂不支持"的路径
- **FR-023**：页脚 MUST 明示三项事实：限流规则、数据为虚构演示数据且定期重置、本平台不提供任何写入接口
- **FR-024**：站点视觉 MUST 采用深色终端风，并遵循既有的现代 SaaS 风格约束
- **FR-025**：站点信息密度 MUST 覆盖完整工具契约、限流数值、安全处置说明与关键取舍理由，而非仅作宣传展示

### 5.4 防滥用与安全

- **FR-026**：系统 MUST 对每个密钥独立限流（每分钟 30 次、每日 500 次），且 MUST NOT 复用既有对话入口的限流额度
- **FR-027**：系统 MUST 在返回用户可编辑的自由文本时，将其明确标记为不可信内容并施加长度截断
- **FR-028**：密钥失效时的错误信息 MUST 为人类可读，并包含重新领取的指引
- **FR-029**：系统 MUST NOT 通过任何工具返回其他访客的密钥信息或系统凭证

### 5.5 与既有机制的协同

- **FR-030**：密钥数据 MUST 在演示数据定期重置中被保留，不得随业务数据一并清除
- **FR-031**：接入端点的服务配置 MUST 支持流式响应不被缓冲，以避免调用表现为长时间无响应
- **FR-032**：部署文档 MUST 同步更新，包含上述服务配置要求

## 6. Key Entities

- **接入密钥（Access Key）**：访客持有的凭证。属性：所属演示身份、只读权限范围、有效期、创建来源、最近使用时间、累计调用次数、吊销状态。与演示身份为多对一关系
- **演示身份（Persona）**：销售 / 主管两种，各自映射到一个既有演示账号，决定该密钥可见的数据范围
- **工具契约（Tool Catalog）**：对外公开的 9 个只读工具的名称、用途、入参、返回结构与示例问法。来源于系统内既有工具定义中标记为只读的部分

---

## 7. Success Criteria

- **SC-001**：访客从打开站点到其 AI 助手返回第一条真实业务数据，中位耗时不超过 3 分钟（不含客户端自身重启时间）
- **SC-002**：完成接入所需填写的必填字段数为 0，所需账号数为 0
- **SC-003**：使用销售身份与主管身份对同一问题提问，返回的数据条目集合可明确区分，且销售结果为主管结果的子集
- **SC-004**：站点提供配置的 5 种客户端，均可不做任何额外改动直接接入成功
- **SC-005**：演示数据定期重置期间，已发放密钥的连接可用性不受影响（重置前后连续调用均成功）
- **SC-006**：单一访客无法通过任何路径使调用量超过既定额度；超额时得到可读提示而非静默失败
- **SC-007**：移动端可完成与 PC 端完全相同的全部操作，无任何功能缺失或降级路径
- ~~**SC-008**：访客在未领取密钥前即可在页面上看到真实调用~~ —— 随 US3 撤销
- **SC-009**：平台不存在任何可导致数据变更的对外能力（工具清单中写操作数量为 0）
- **SC-010**：技术读者不接入即可从站点获取全部 9 个工具的完整契约信息

## 8. Assumptions

- 演示账号 `sales01`（王小明）与 `manager01`（陈队长）持续存在于种子数据中，且其数据可见范围配置保持现状
- 访客自备支持 MCP 的客户端，本平台不负责其安装与调试
- 平台承载的全部数据均为虚构演示数据，不含任何真实客户信息，因此公开发放凭证的数据泄露风险为零
- 数据可见性规则、权限校验与工具执行入口沿用系统既有实现，本 spec 不重建
- 演示数据的定期重置机制沿用既有实现，本 spec 只要求密钥数据不被其清除
- 密钥有效期 7 天，是基于"演示数据每 30 分钟即重置、无需更长留存"这一前提的取值
- 访客可能通过分享传播密钥，这是被鼓励的行为而非需要防范的风险

## 9. Dependencies

- 既有的工具定义与统一执行入口（含其只读标记）
