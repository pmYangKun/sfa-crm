# Contract: 对外暴露的 MCP 工具（9 个，全只读）

**Feature**: 005-mcp-open-platform
**来源**: `src/backend/app/services/agent_service.py` → `TOOL_DEFINITIONS` 中 `mode == "read"` 的条目
**过滤方式**: 程序化过滤（`if t["mode"] == "read"`），**不得手工维护清单**（FR-011）

---

## 通用约定

- **全部只读。** 任何工具都不产生数据变更
- **数据范围由密钥身份决定。** 同一工具、同一参数，销售密钥与主管密钥返回的集合不同（FR-013）
- **工具清单与身份无关。** 两种身份看到完全相同的 9 个工具（FR-014）
- **越权访问不区分响应。** 请求可见范围外的标识时，返回与"不存在"相同的结果，避免被用于探测
- **自由文本须消毒。** 凡返回用户可编辑文本的字段，须包裹不可信标记并截断长度（FR-027）

---

## 工具清单

### 1. `search_leads` — 搜索线索

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `search` | string | 否 | 公司名关键词 |
| `region` | string | 否 | 大区 |

**返回：** 可见范围内的线索列表
**示例问法：** "北京大区有哪些线索？"

---

### 2. `get_lead_detail` — 线索详情

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `lead_id` | string | **是** | 线索标识 |

**返回：** 线索详情 + 联系人 + 详情页地址
**示例问法：** "XX 公司这单什么情况？"

---

### 3. `get_followup_history` — 跟进记录历史

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `lead_id` | string | **是** | 线索标识 |

**返回：** 跟进记录时间线
**⚠️ 注入消毒重点：** 本工具是 9 个中唯一大量输出访客可编辑自由文本的，是 prompt injection 的主要载体，消毒与截断必须在此生效
**示例问法：** "这单最近都聊了什么？"

---

### 4. `get_lead_meddicc` — MEDDICC 评估

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `lead_id` | string | **是** | 线索标识 |

**返回：** 总分 + 7 维状态 + 各维证据条目
**注意：** 工具描述中已声明"必须使用本工具的持久化结果，不得自行从跟进记录推算"，该语义须原样保留到 MCP 层，否则外部 agent 会重蹈内置 Copilot 曾犯的错
**示例问法：** "这单 MEDDICC 打几分，弱在哪一维？"

---

### 5. `list_customers` — 客户列表

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `search` | string | 否 | 公司名关键词 |

**返回：** 可见范围内的客户列表
**示例问法：** "我有哪些客户？"

---

### 6. `scan_team_warnings` — 风险单扫描

**参数：** 无

**返回：** 可见范围内所有触发 warning 的线索 + 各自命中的 warning 代码
**成本提示：** 聚合类，须受限流保护
**示例问法：** "我团队哪几单有风险？"

---

### 7. `team_meddicc_summary` — 团队 MEDDICC 汇总

**参数：** 无

**返回：** 平均分 + 7 维亮灯密度 + 表现最好/最弱的销售各 3 名
**成本提示：** 聚合类
**示例问法：** "团队健康度怎么样？"

---

### 8. `top_attention_deals` — 重点关注单

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `limit` | integer | 否 | 返回条数，默认 5 |

**返回：** 按 warning 数、分数反向、金额加权排序的线索
**示例问法：** "今天我该重点看哪几单？"

---

### 9. `forecast_category_distribution` — 预测分类分布

**参数：** 无

**返回：** 6 个预测分类各自的条数、warning 数、总金额
**注意：** 既有工具描述约定"默认只播报条数与 warning 数，金额仅在用户明确询问时给出"，该语义须保留
**示例问法：** "团队 pipeline 分布如何？"

---

## 明确不暴露（6 个，`mode == "navigate"`）

`navigate_create_lead` / `navigate_log_followup` / `navigate_create_key_event` / `navigate_convert_lead` / `navigate_release_lead` / `navigate_mark_lost`

**原因：** 这些工具不写库，只返回目标页面地址并向浏览器传递预填数据，依赖人在界面上点击确认完成提交。MCP 调用方没有浏览器，收到的只会是一句无法执行的跳转指引（FR-012）。

**契约保证：** 工具列举结果中**不出现**上述名称；直接按名调用返回"工具不存在"。

---

## 契约测试要求

1. 工具列举返回且仅返回 9 个工具，名称与本文一致
2. 6 个 `navigate_*` 名称在列举结果中不存在，按名调用返回未找到
3. 每个工具的入参 schema 与 `TOOL_DEFINITIONS` 完全一致（防止转换过程丢失必填标记）
4. 销售密钥与主管密钥的列举结果**完全相同**
5. 同一问题下，销售密钥返回的数据集合是主管密钥返回集合的子集
6. `get_followup_history` 返回内容中，用户自由文本字段带不可信标记且长度受限
