## 一、项目定位与技术栈

**项目目标：** 用 Spec Coding 方式从零构建 SFA CRM，验证"方法论 → AI 规范 → 复杂系统落地"这条链路。

- **GitHub：** `https://github.com/pmYangKun/sfa-crm`（公开仓库，**主分支 master 不是 main**）
- **技术栈：** Next.js + FastAPI + SQLite + Docker Compose + Vercel AI SDK
- **线上：** https://crm.pmyangkun.com （腾讯云，与 Homepage 共用一台；ICP 京ICP备2026025674号）
  > 服务器 IP / SSH 别名 / 密钥路径等接入信息**不写进本仓库**（公开），见用户级 `reference_crm_server_runbook.md`
- **本仓库没有 alembic** —— 新增表 / SystemConfig 项必须显式跑 `init_db()`（幂等）

## 三、重大设计决策（设计阶段确定，至今未变）

| 决策 | 结论 |
|---|---|
| 线索 vs 客户 | **独立对象**，Lead 有状态，Customer 无状态，转化时归档 + 迁移 |
| 权限 | RBAC 四表（Role/Permission/UserRole/RolePermission）+ **DataScope 解耦** |
| 数据可见性 | `self_only` / `current_node` / `current_and_below` / `selected_nodes` / `all` |
| 业务规则 | **配置驱动**（SystemConfig 表），不硬编码 |
| AI Agent | GUI 和 Agent **共用同一套 API**，Ontology Actions → Tool Use |
| Skill 系统 | 提示词文本存 DB，LLM 通过工具调用检索，Provider 可切换 |

### 工具层的两种模式（贯穿全项目的关键结构）

`TOOL_DEFINITIONS` 里 15 个工具分两类，**这个切分是后来很多事情的地基**：

- **`mode == "read"`（9 个）** —— 直接执行返回数据。MCP 开放平台按这个字段**程序化过滤**对外暴露，不维护人工白名单
- **`mode == "navigate"`（6 个）** —— **一行数据都不写**，只返回导航指令 + 表单预填，最后一下必须人点确认

> 这就是"读放开、写收口"。写操作永不对外暴露的理由也在这儿：MCP 调用方没有浏览器，拿到跳转指令也执行不了。

## 四、发布 / 部署约定（2026-05-07 三修定稿）

**核心规则：公网永远跟 master HEAD 跑。** 每个大 spec 收口（PR merge 后）立即部署最新版。**不按 tag 切回旧版本演示历史。**

**为什么这么简化：**
1. 切 tag 部署需要 DB schema 同步管理（每个 tag 得带能 rebuild 的迁移脚本），工程量大
2. SQLite + 30min 重置场景下 DB 跟代码绑死，回滚要彻底删 DB 重建
3. **读者不会真去对每篇文章找对应版本**——文章说的是"那时做了什么"，公网展示"现在长啥样"，读老文章看新功能反而是惊喜
4. 演示视频录完即归档，不需要回放

**为什么不会 DB 与代码不一致：** 永远向前部署、永远跑最新、永远不回滚 → 没有错配的可能。

**Git tag 仍然打**，但只作 **code state marker**（"这个 commit 就是 spec NNN 的最终态"），方便 diff/blame/史料检索，**不作为部署目标**。当前 tag 见 `current.md`。

**部署工作流：**
1. spec 在分支开发 → PR 合 master → 给 merge commit 打 `v-specNNN` annotated tag → push origin（含 tag）
2. 部署 master HEAD 到公网（本地 `git archive` + scp，增量 7 步见用户级 `feedback_deploy_vocab`）
   ⚠️ **若本次上线新增了数据表或 SystemConfig 项，重启服务不会建表，必须显式跑一次 `init_db()`**。spec 005 部署时踩过：`mcp_token` 表没建，领密钥直接 500
3. master 继续跑下一个 spec，公网随之滚动

**禁止：**
- 按 tag 切回旧版本演示（无论为对齐文章还是录视频）
- 不打 tag 就 merge 大 spec 进 master
- **在文章正文出现 `v-specNNN` / spec 编号 / git tag URL**（skill `create-claudegg-article` 的硬规矩）

**已废弃的老规则（2026-05-07 三修废）：**
- ❌ "公网部署只跟 git tag 走，不跟 master HEAD 跑"——反过来了
- ❌ "切 tag 时 DB rebuild + 重灌 demo 数据"——永远不切回去，不需要这条纪律
